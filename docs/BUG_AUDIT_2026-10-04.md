# 0.2.3 發佈後 bug 審查（2026-10-04）

本報告先記錄 0.2.3 的問題與原始證據，再記錄使用者要求的 0.2.4 修正。審查階段使用 Android 14／API 34、4 KB page size 的 root 實機，重現 fixture 只限獨立 Debug 套件，不對正式 App 注入異常設定或清除資料。

## 已確認的 0.2.3 問題（已於 0.2.4 修正）

### 1. 查詢等待期間才出現的跳點漏掉地理資訊（P2）

- 位置：`TracerouteHandler.kt`，`MainWSHandler` 約 314–360 行。
- 重現：第 1 跳尚無 IP，第 2 跳已出現；第 2 跳的查詢等待期間，第 1 跳才寫入回環 IP。
- 預期：第 1 跳在下一輪被處理並標示 `RFC1122`。
- 實際：所有列都已有 IP 後迴圈立即結束，第 1 跳 ASN／分類仍為空字串。
- 證據：`GeoProcessingAuditTest.hopArrivingDuringLookupIsNotSkipped` 以本機隨機埠的 TCP socket 暫停 TLS handshake，實際呼叫現有 `MainWSHandler`；斷言得到 `expected RFC1122, actual empty`。不需要有效 token 或修改正式後端。
- 原因：終止條件只檢查 IP 非空，沒有確認每個已出現的有效 IP 都已完成 metadata 處理。受影響列也未加入地圖資料。
- 修正方向：明確追蹤每列 metadata 的完成／失敗狀態；新出現的跳點須處理後才能結束，並保持取消與失敗的有界行為。

### 2. 後端不可用時，本地保留位址分類也消失（P2）

- 位置：`TracerouteHandler.kt`，`MainWSHandler` 約 307–324 行。
- 重現：Debug 設定中將兩個後端 DNS 目標設為回環 IP，使後端連線失敗，再追蹤 `127.0.0.1`。
- 預期：原生 ping 仍完成，本地 CIDR 表仍顯示 `RFC1122`；外部 ASN／地理資訊可標示不可用。
- 實際：追蹤最後可完成並複製，但沒有 `RFC1122`。
- 證據：`OfflineGeoAuditTest.localAddressClassificationDoesNotRequireBackend` 已在實機失敗，訊息為 `Loopback classification is missing when the backend is unavailable`。
- 原因：等待 token／後端 IP 逾時即整體 return，後方不需要網路的 `reservedIPFilter` 根本沒有執行。
- 修正方向：本地分類與外部查詢分開；服務不可用不能阻止本地可確定的結果。

### 3. 異常設定中的 NaN 導致設定頁崩潰（P2）

- 位置：`MainActivity.kt` 還原設定；`Settings.kt` 約 133–134、467 行。
- 重現：僅在 Debug fixture 寫入 `"traceTimeout":"NaN"`，冷啟動後開啟 Settings。
- 實際：普通 App 操作（不經 instrumentation）取得 `FATAL EXCEPTION: main`、`IllegalArgumentException: Cannot round NaN value`，堆疊定位 `NumberSliderSetting`。
- 原因：`toFloatOrNull()` 可能接受非有限值，`coerceIn` 不會把 NaN 變成合法數值；繪製時 `roundToInt()` 拋出例外。封包數使用相同還原流程，也需一併檢查，但本輪直接崩潰重現使用的是逾時值。
- 限制：一般設定 UI 不會寫出 NaN；這是異常／手動修改設定資料的容錯問題，不能據此推定使用者所有日常崩潰都由它造成。
- 修正方向：載入時檢查數值是否有限、在允許範圍內並符合整數參數要求；不合法時採用預設值，繪製端亦須防禦。

## 0.2.3 原始驗證結果與限制

- 原有 4 項 UI 回歸全部通過：十萬字元 URL、錯誤輸入、CDN 主機解析／清除／IME、停止重跑及 Activity 重建。
- 新增 7 項操作／受控連線測試：5 通過、上述問題 1 與 2 的 2 個重現斷言失敗。
- 額外以不經測試框架的冷啟動／設定頁操作確認問題 3 的真正 App 崩潰；不是僅由靜態推測或測試框架錯誤推定。
- 18 個 JVM 測試經強制重跑全數通過。lint 最終為 0 errors、11 個非阻擋更新／既有資源目錄警告。
- 重建測試 APK 後再以獨立本機 ADB 服務收集無線複核結果：3 tests、2 failures。正常設定儲存與冷啟動通過，兩個 metadata 缺陷再次取得同樣的斷言結果，沒有把 ADB shell 的程序退出碼當成測試成功。
- 來源隱私規則檢查與 `git diff --check` 通過；未產生待推送 commit 或新的正式簽署產物，不宣稱已完成新版本的發佈審查。
- USB 曾中斷，並非 App crash 的證據；已改用使用者授權的無線 ADB。instrumentation 的異常設定測試曾被系統以 ANR 終止，主執行緒停在 Espresso idle 等待，故另以非 instrumentation 操作確認真正的 NaN 崩潰。
- 程式碼審查另注意到地圖 HTTP 請求沒有 total call timeout，且同步 `execute()` 沒有連結 coroutine 取消；慢速持續回應時可能拖延 Stop。這仍是待重現風險，不列為本輪第四個已確認缺陷。
- 本次取樣不能證明所有裝置、網路與場景均無其他 bugs；未測試 Google Play 發佈或更動後端服務。

## 重跑方式

使用 JDK 21 與 Android SDK，單一 Gradle 建置依序執行：

```text
gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

用 ADB 安裝 Debug App 與 androidTest APK，再透過 `am instrument -w -r -e class` 分別執行以下類別；有多種連線時必須明確選擇同一個實體裝置的單一 transport，不能讓 Gradle 對 USB／無線兩個連線同時測試同一支手機。

- `com.surfaceocean.nexttraceroute.TraceUiRegressionTest`
- `com.surfaceocean.nexttraceroute.TraceDeviceAuditTest`
- `com.surfaceocean.nexttraceroute.GeoProcessingAuditTest`
- `com.surfaceocean.nexttraceroute.OfflineGeoAuditTest`
- `com.surfaceocean.nexttraceroute.StoredSettingsAuditTest`（0.2.3 可能終止整個測試程序；0.2.4 應通過）
- `com.surfaceocean.nexttraceroute.DisplayLanguageTest`（0.2.4 新增）

`AuditSettingsRule` 只允許 Debug package，正常結束會還原原始設定。若程序被系統終止，先停止 Debug App，再檢查其 `files/`：

- 若有 `settings.audit-backup`，以該備份恢復 `settings.json`。
- 若有 `settings.audit-was-absent`，原本沒有設定檔，只移除本輪新增的 `settings.json` 與不存在標記。
- 不得對正式 App 套用這些測試 fixture 或清除其資料。

審查結束時已執行恢復、確認兩個標記均不存在，Debug 冷啟動成功。上述故意揭露缺陷的測試必須在修正後通過，不可忽略。

## 0.2.4 修正與回歸

- `validIntegerSetting` 在設定還原時統一檢查有限值、整數及範圍；Slider 繪製端也防禦 NaN。實機測試同時注入 NaN、Infinity 及極大值，確認設定頁可開啟、儲存並回復 1 秒／5 個封包／30 跳的預設值。
- metadata 迴圈以每列完成狀態作結束條件，查詢期間才出現的跳點會在下一輪處理；本地保留位址不再等待 token 或後端。外部查詢不可用時明確標記失敗，避免無限等待。
- 地圖請求與 coroutine 取消連動，加入 10 秒整體逾時及 8 KiB 回應上限。受控 socket 測試確認讀取中取消會關閉連線；此為原先待重現風險的防禦性改善，不追溯宣稱已在 0.2.3 實機重現。
- 新增中文預設、英式英文第二選項，與 API 回應語言分離；切換、重建與語系 `en-GB` 有自動化驗證。所有畫面和操作提示集中於 Android 語言資源。
- 24 項 JVM 測試通過；Android 14 無線 ADB 實機及 API 37／16 KB 模擬器均取得 `OK (13 tests)`，包含三個已知問題與語言切換，不以 shell 退出碼取代測試結果。
- 維持單一 Gradle 建置流程，未加入新依賴或更換簽署金鑰。發佈簽章、產物隱私及遠端資產核對結果另記於 `HANDOFF.md`。
