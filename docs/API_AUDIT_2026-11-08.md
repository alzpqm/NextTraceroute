# NextTrace API v3／v4 檢查（2026-11-08）

> 本文保留 0.2.6 接入前的檢查結果；後續 0.3.0 已新增 v4 與官網驗證後的授權自動匯入，實作及驗證見 `docs/releases/v0.3.0.md`。

## 結論

NextTrace API v4 已存在，但未全面取代 v3。官方核心穩定版 v1.7.6 仍在沒有 v4 token 時選用 v3；本次連線檢查亦確認 App 現行 v3 流程可取得地理資訊。Android 0.2.6 尚未實作 v4。

## 上游停用及服務限制公告

補查官方網站的 `announcement.md`、修改紀錄、Release、PR 與 Discussions 後，截至 2026-11-08 未找到 v3 全面停用的固定日期。這不等於服務條件沒有調整，也不代表官方保證長期提供 v3。

- 公告標示 **2026-08-22 19:00 UTC+8**：原文為「我们已调降 NextTrace v3 API 单次验证授权所需的 credits」，並建議現有額度不足者使用 v4。沒有公布調整前後數值、QPS 或資料精度／優先權變化；不能僅憑這個措辭推算每次驗證可查詢的次數或具體降權幅度。
- 公告標示 **2026-08-14**：v4 token 的可用額度翻倍。這不是 v3 的停用日期。
- 公告標示 **2026-08-06**：對接官方 API 的第三方網站、App、Bot 等需確認授權；既有社群專案有 30 日過渡期，之後未完成確認的呼叫可能無法繼續取得服務。公告未列固定截止日，已有獨立約定者依原約定；不能把它解讀為所有 v3 使用者同日停用，也不能僅從本 Fork 的程式碼確認其服務授權狀態。
- 公告中的「最早 2027 年」指命令列預設改為 MTR 顯示模式，並不是 API v3 的停用時間表。

公告文字的標示日期與網站 repository 收錄日期不同；上述日期依公告原文列示，不以 Git commit 時間替代。核對版本為網站提交 `b505ac77f7ecdd7f5e598ebbfc1fff84bfb8522e`。

## 呼叫方式

| 項目 | Android 0.2.6 | 官方 v4 |
| --- | --- | --- |
| 地理資訊 | `wss://<host>/v3/ipGeoWs`，傳送 IP 文字 | `GET https://api.nxtrace.org/v4/ipGeo?ip=<ip>`，沒有 JSON body |
| 授權 | PoW 取得暫時 token，使用 `Authorization: Bearer` | 使用者提供 v4 token，使用 `X-NextTrace-Token` |
| 無 v4 token | 現有 v3 流程 | 官方核心仍選用 v3 |
| v4 授權或配額錯誤 | 尚未實作 | 處理 401／429，不自動回退 v3 |
| 地圖 | 獨立 `POST /tracemap/api` | 不應因新增 v4 GeoIP 而推定地圖也有 v4 路徑 |

Android 來源位於 `TracerouteHandler.kt` 的 `requestApiToken`、`geoSession` 及地圖請求；`GeoApi.kt` 負責 WebSocket 回覆解析。`NEXTTRACE_CORE_VERSION = "1.7.2"` 用於版本標示及 User-Agent，並不是載入或執行官方核心程式；修改該字串不會自動獲得 v4 功能。

## 本次驗證

- 核對官方核心穩定版 v1.7.6 的 README、v3／v4 實作及 PoW 程式；官方 Android 上游的最新提交仍為 v0.1.7，未發現可直接套用的 v4 移植。
- 以現行 App 的預設 hostname、API DNS 路由及 User-Agent 進行少量直接 TLS 連線檢查，憑證驗證保持啟用。v3 challenge 與 submit 均回傳 HTTP 200；WebSocket 升級回傳 101；以公開 DNS 服務位址作單次查詢，回覆位址相符且包含 AS 欄位。
- v3 檢查使用主機端獨立測試程式重現協定，不是 Android 實機或整個 App 的操作測試。暫時 token 僅保留在測試程序記憶體，未寫入來源、證據或紀錄。
- v4 不帶 token 的請求回傳 HTTP 401 與 JSON error。未取得有效 v4 token，因此尚未驗證成功查詢、真實配額、token 過期及 Android 上的 v4 行為。

## 後續接入條件

新增 v4 應另建 HTTP 查詢路徑及使用者 token 設定，保留未設定 token 時的 v3 行為。不能直接替換路徑中的版本字串，也不能假定 PoW token 可作為 v4 token 使用。

Token 應只送往預期的 HTTPS 服務標頭，不放在網址、日誌、原始碼或明文設定／備份中；需要處理過期、401、429、取消、逾時、回應大小與回覆位址驗證。官方 token 頁面當次標示有效期為 7 天，實作時仍應依服務回覆處理期限及配額。

`nexttrace -x` 的暫存檔屬於執行該命令的作業系統環境，包含同使用者的 fallback 檔；它不會自動把 token 傳給 Android App。使用者貼出的命令列輸入提示並不是 token，也不能當作已完成設定的證據。

本輪只完成檢查及文件紀錄，沒有變更 App 的 API 行為、版本號或正式發布。
